## 🤔 Что это и зачем нужно?

### 🎯 Представьте ситуацию...

Вы работаете над документацией для EMH. У вас есть файл `Readme.md`. Вы его редактируете, сохраняете. Через неделю понимаете, что сделали ошибку, но уже не помните, что именно изменили. **Знакомо?** 😅

**Git и Gitea решают эту проблему!**

### 📖 Что такое Git?

**Git** — это система, которая запоминает **ВСЕ изменения** в ваших файлах. Как "машина времени" для кода и документов.

**Аналогия из жизни:**
> Представьте, что вы пишете книгу. После каждой главы вы делаете фотокопию и кладёте в сейф с датой. Если что-то не так — всегда можете вернуться к любой версии.

### 🌐 Что такое Gitea?

**Gitea** — это веб-сайт (как Google Drive, но для кода), где хранятся ваши проекты.

**Преимущества:**
- 🔄 Все сотрудники работают с **одной версией** документов
- 📜 Видна **история изменений** (кто, когда, что изменил)
- 💬 Можно **обсуждать** изменения прямо в интерфейсе
- 🔒 **Безопасное хранение** (резервные копии)

### 🏥 Зачем это IT отделу больницы?

| Проблема без Git | Решение с Git |
|------------------|---------------|
| 📁 "У меня локально работает, а у тебя нет" | ✅ Все работают с одной версией кода |
| 🤷 "Кто удалил важную строку?" | ✅ Видна история всех изменений |
| 💥 "Я случайно всё сломал!" | ✅ Можно откатиться к рабочей версии |
| 📝 "Какая версия документации актуальная?" | ✅ Всегда есть одна "главная" версия |
| 👥 "Мы работаем над одним файлом параллельно" | ✅ Git сам объединяет изменения |

## 📚 Словарь терминов

Прежде чем начать, давайте разберём основные понятия:

| Термин | Простое объяснение | Пример |
|--------|-------------------|--------|
| 📦 **Репозиторий (Repository)** | Папка с проектом + вся история изменений | `EMH.Documentation` |
| 📋 **Клонирование (Clone)** | Скачать копию репозитория на свой компьютер | "Скачать EMH к себе" |
| ✏️ **Коммит (Commit)** | Сохранение изменений с комментарием | "Добавил раздел о миграциях" |
| 📤 **Push** | Отправить свои изменения на сервер | "Загрузить работу в Gitea" |
| 📥 **Pull** | Получить свежие изменения с сервера | "Скачать обновления от коллег" |
| 🌿 **Ветка (Branch)** | Параллельная версия проекта | "Работаю над новой фичей отдельно" |
| 🔀 **Merge** | Объединение изменений из разных веток | "Влил свою работу в основную версию" |
| ⚔️ **Конфликт (Conflict)** | Когда два человека изменили одну строку | "Нужно вручную решить, чья версия правильная" |
| 📊 **Staging Area** | "Корзина" для подготовленных изменений | "Собрал файлы, которые хочу сохранить" |

## 🛠️ Установка инструментов

### Шаг 1: Установка Git

#### 🪟 Для Windows:

1. Скачайте Git с официального сайта:  
   👉 https://git-scm.com/download/win

2. Запустите установщик
3. **Важно:** На всех шагах оставляйте настройки **по умолчанию** (просто нажимайте "Next")
4. После установки откройте **PowerShell** и проверьте:

```powershell
git --version
```

Должно показать что-то вроде: `git version 2.43.0.windows.1`

#### 🐧 Для Linux:

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install git

# CentOS/RHEL
sudo yum install git
```

Проверка:
```bash
git --version
```

### Шаг 2: Установка VS Code (рекомендуется)

VS Code — это редактор кода с удобной интеграцией Git.

👉 Скачать: https://code.visualstudio.com/

**Преимущества VS Code для Git:**
- 🎨 Визуальный интерфейс (не нужно помнить команды)
- 👀 Удобный просмотр изменений (diff)
- 🔔 Уведомления о конфликтах
- 📊 Графическое отображение истории

## 🔧 Первая настройка Git

После установки нужно "представиться" Git'у:

### В PowerShell выполните:

```powershell
# Укажите ваше имя (как в корпоративной почте)
git config --global user.name "Иванов Иван Иванович"

# Укажите вашу корпоративную почту
git config --global user.email "ivanov@emh-hospital.ru"

# Настройте редактор по умолчанию (VS Code)
git config --global core.editor "code --wait"

# Настройте ветку по умолчанию
git config --global init.defaultBranch main
```

### Проверьте настройки:

```powershell
git config --list
```

Должно вывести:
```
user.name=Иванов Иван Иванович
user.email=ivanov@emh-hospital.ru
core.editor=code --wait
init.defaultBranch=main
```

✅ **Отлично! Git настроен.**

## 📦 Работа с репозиторием EMH

### Получение адреса репозитория

1. Откройте [Gitea в браузере](http://192.168.7.43:10010)
2. Перейдите в репозиторий `EMH.Documentation`
3. Нажмите кнопку **"Clone"** (зелёная кнопка справа)
4. Скопируйте **HTTPS URL**

Пример: `https://gitea.emh-hospital.ru/it-department/EMH.Documentation.git`

### Клонирование репозитория

#### Вариант 1: Через PowerShell (классический способ)

```powershell
# Перейдите в папку, где хотите хранить проекты
cd C:\Projects

# Клонируйте репозиторий
git clone https://gitea.emh-hospital.ru/it-department/EMH.Documentation.git

# Перейдите в папку проекта
cd EMH.Documentation
```

#### Вариант 2: Через VS Code (проще!)

1. Откройте VS Code
2. Нажмите `Ctrl+Shift+P` (или `Cmd+Shift+P` на Mac)
3. Введите: `Git: Clone`
4. Вставьте URL репозитория
5. Выберите папку для сохранения
6. Нажмите **"Open"** когда предложит открыть проект

✅ **Готово! Репозиторий клонирован.**

## 🔄 Типичный рабочий процесс

### 📋 Сценарий: Вы хотите добавить новую статью в документацию

#### Шаг 1: Обновите локальную копию

**ВСЕГДА начинайте работу с этого шага!**

```powershell
# Убедитесь, что вы в папке проекта
cd C:\Projects\EMH.Documentation

# Получите свежие изменения от коллег
git pull
```

#### Шаг 2: Создайте новый файл

```powershell
# Создайте папку для новой статьи
mkdir UserGuides\NewFeature

# Создайте файл
code UserGuides\NewFeature\Guide.md
```

Напишите содержимое в VS Code и сохраните (`Ctrl+S`).

#### Шаг 3: Проверьте, что изменилось

```powershell
git status
```

Увидите что-то вроде:
```
On branch main
Your branch is up to date with 'origin/main'.

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        UserGuides/NewFeature/Guide.md

nothing added to commit but untracked files present
```

#### Шаг 4: Добавьте изменения в "корзину" (staging)

```powershell
# Добавить конкретный файл
git add UserGuides/NewFeature/Guide.md

# ИЛИ добавить все изменения сразу
git add .
```

Проверьте снова:
```powershell
git status
```

Теперь увидите:
```
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   UserGuides/NewFeature/Guide.md
```

#### Шаг 5: Сделайте коммит (сохраните изменения)

```powershell
git commit -m "docs: add guide for new feature"
```

**💡 Правило хороших сообщений коммитов:**

| ✅ Хорошо | ❌ Плохо |
|-----------|----------|
| `docs: add user guide for Gitea` | `update` |
| `feat: add migration script` | `fix` |
| `fix: correct typo in readme` | `wip` |
| `refactor: simplify database connection` | `changes` |

**Формат:** `тип: краткое описание`

**Типы:**
- `docs` — изменения в документации
- `feat` — новая функциональность
- `fix` — исправление ошибки
- `refactor` — улучшение кода без изменения логики
- `chore` — технические изменения (обновление зависимостей и т.п.)

#### Шаг 6: Отправьте изменения на сервер

```powershell
git push
```

✅ **Готово! Ваши изменения теперь доступны всем коллегам.**

## 🎨 Работа через VS Code (рекомендуется)

VS Code делает работу с Git **намного проще**!

### 📍 Где найти Git в VS Code?

Посмотрите на **левую панель** — там иконка с ветками (🌿)

### 🔄 Обновление (Pull)

1. Нажмите на иконку Git (🌿) слева
2. Нажмите **"..."** (три точки) вверху панели
3. Выберите **"Pull"**

**Или** используйте кнопку синхронизации в **нижней левой части** окна (🔄)

### ✏️ Коммит изменений

1. Измените файлы и сохраните (`Ctrl+S`)
2. В панели Git увидите список изменённых файлов
3. Нажмите **"+"** рядом с файлом (или **"+"** на "Changes" для всех)
4. Введите сообщение коммита в поле сверху
5. Нажмите **"✓ Commit"** (галочка)

### 📤 Отправка (Push)

После коммита:
1. Нажмите **"..."** → **"Push"**
2. **Или** используйте кнопку синхронизации (🔄) внизу

### 👀 Просмотр истории

1. Нажмите **"..."** → **"View History"**
2. Увидите все коммиты с датами и авторами
3. Кликните на коммит — увидите, что изменилось

### 🎯 Полезные горячие клавиши

| Действие | Горячие клавиши |
|----------|-----------------|
| Открыть панель Git | `Ctrl+Shift+G` |
| Коммит (с сообщением) | `Ctrl+Enter` (в поле сообщения) |
| Синхронизация (Pull + Push) | Клик на 🔄 внизу |
| Открыть терминал | `Ctrl+~` (тильда) |

## ⚠️ Частые ошибки и решения

### ❌ Ошибка 1: "fatal: not a git repository"

**Что означает:** Вы не в папке с репозиторием

**Решение:**
```powershell
# Перейдите в папку проекта
cd C:\Projects\EMH.Documentation

# Проверьте
git status
```

---

### ❌ Ошибка 2: "error: failed to push some refs"

**Что означает:** Кто-то уже отправил изменения, а вы нет

**Решение:**
```powershell
# Сначала получите обновления
git pull

# Потом отправьте свои
git push
```

---

### ❌ Ошибка 3: "CONFLICT (content): Merge conflict"

**Что означает:** Вы и коллега изменили одну и ту же строку

**Решение:**

1. Откройте файл с конфликтом в VS Code
2. Увидите метки:
   ```
   <<<<<<< HEAD
   Ваш вариант
   =======
   Вариант коллеги
   >>>>>>> branch-name
   ```
3. Выберите правильный вариант (или объедините)
4. Удалите метки (`<<<<<<<`, `=======`, `>>>>>>>`)
5. Сохраните файл
6. Добавьте и закоммитьте:
   ```powershell
   git add .
   git commit -m "resolve: merge conflict in file.md"
   git push
   ```

**💡 Совет:** В VS Code конфликты решаются кликами мыши — он покажет кнопки "Accept Current Change", "Accept Incoming Change" и т.д.

---

### ❌ Ошибка 4: "Your local changes would be overwritten"

**Что означает:** У вас есть несохранённые изменения

**Решение:**

**Вариант A: Сохранить свои изменения**
```powershell
git add .
git commit -m "wip: save my changes"
git pull
git push
```

**Вариант B: Отменить свои изменения (ОСТОРОЖНО!)**
```powershell
# Отменить изменения в конкретном файле
git checkout -- path/to/file.md

# Отменить ВСЕ изменения (необратимо!)
git reset --hard HEAD
```

---

### ❌ Ошибка 5: "Authentication failed"

**Что означает:** Неправильный логин/пароль или токен

**Решение:**

1. Уточните у руководителя ваш логин в Gitea
2. Проверьте, что используете **Personal Access Token** вместо пароля
3. Как создать токен:
   - Зайдите в Gitea → Настройки (Settings) → Приложения (Applications)
   - Создайте новый токен с правами `repo`
   - Используйте этот токен как пароль при `git push/pull`

---

### ❌ Ошибка 6: Забыли сделать коммит, а уже начали новую работу

**Решение:**
```powershell
# Посмотреть, что изменилось
git status

# Добавить и закоммитить
git add .
git commit -m "docs: forgot to commit previous changes"
```
