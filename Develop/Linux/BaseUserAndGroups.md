# 📘 Гайд 2. Пользователи и Права доступа

**Цель:** Понимать, почему система пишет `Permission denied`, кто такой `www-data`, и как безопасно давать доступ к файлам и папкам, не ломая при этом сервисы.

---

## 🧠 Часть 1. Как Linux думает о пользователях

В Linux **каждый** файл и **каждый** процесс принадлежит какому-то пользователю. Это не просто «учётка для входа», это фундамент безопасности.

Три ключевых понятия:

| Понятие | Что это | Пример |
|---------|---------|--------|
| **User (пользователь)** | Конкретный «актёр» в системе | `admin`, `postgres`, `www-data` |
| **Group (группа)** | Набор пользователей с общими правами | `docker`, `sudo`, `staff` |
| **Others (остальные)** | Все, кто не владелец и не в группе | Любой другой пользователь |

> 💡 **Важно:** В Linux есть «системные» пользователи, которые не предназначены для входа человеком. Например, `www-data` (веб-сервер), `postgres` (база данных), `minio` (хранилище). Они нужны, чтобы сервисы работали с минимальными правами. Если сервис взломают — злоумышленник не получит root.

## 👤 Часть 2. Кто я и кто здесь ещё?

### 1. Кто я сейчас?
```bash
whoami
# Вывод: admin
```

### 2. Подробная информация о текущем пользователе
```bash
id
# Вывод: uid=1000(admin) gid=1000(admin) groups=1000(admin),27(sudo),999(docker)
```
*Здесь видно:*
- *`uid=1000` — ваш числовой ID пользователя*
- *`gid=1000` — ваша основная группа*
- *`groups=...` — все группы, в которых вы состоите (включая `sudo` и `docker`)*

### 3. Кто ещё сидит на сервере?
```bash
w
# Покажет всех залогиненных пользователей, их IP и что они делают прямо сейчас
```

### 4. Список всех пользователей в системе
```bash
cat /etc/passwd
```
*Не пугайтесь длинного списка. Большинство строк — это системные пользователи (`daemon`, `bin`, `sys`, `www-data`, `postgres` и т.д.). Реальные люди обычно имеют `uid >= 1000`.*

```bash
# Показать только «живых» пользователей (uid >= 1000):
awk -F: '$3 >= 1000 && $3 < 65534 {print $1}' /etc/passwd
```

## 🛠 Часть 3. Управление пользователями

### 1. Создание нового пользователя
```bash
sudo useradd -m -s /bin/bash ivanov
```
*Флаги:*
- *`-m` — создать домашнюю папку `/home/ivanov` (без этого флага папка НЕ создастся!)*
- *`-s /bin/bash` — назначить оболочку bash (по умолчанию может быть `/bin/sh`, что неудобно)*

### 2. Задать пароль
```bash
sudo passwd ivanov
# Система попросит ввести пароль дважды
```

### 3. Добавить пользователя в группу
```bash
sudo usermod -aG docker ivanov
sudo usermod -aG sudo ivanov
```
*Флаг `-aG` (append to Groups) — **добавить** в группу, не удаляя из остальных.*

> 🚨 **ОШИБКА НОВИЧКА:** Если написать `usermod -G docker ivanov` (без `-a`), то Иванов **потеряет** все остальные группы и останется только в `docker`. Всегда используйте `-aG`!

### 4. Проверить, что всё применилось
```bash
id ivanov
# Вывод: uid=1001(ivanov) gid=1001(ivanov) groups=1001(ivanov),27(sudo),999(docker)
```

> ⚠️ **Важно:** Изменения групп вступают в силу только после **перелогина** пользователя. Если Иванов сейчас залогинен, ему нужно выйти и зайти заново (или выполнить `newgrp docker`).

### 5. Удаление пользователя
```bash
sudo userdel ivanov          # Удалить пользователя, но оставить его файлы
sudo userdel -r ivanov       # Удалить пользователя ВМЕСТЕ с домашней папкой
```

## 🔐 Часть 4. Права доступа: как читать `rwxr-xr--`

Когда вы делаете `ls -l`, вы видите что-то такое:

```
-rw-r--r--  1 admin  staff   4096 Oct  6 10:30 config.yml
drwxr-x---  3 www-data www-data 4096 Oct  6 09:15 uploads/
```

Первый столбец — это **права доступа**. Разберём по буквам:

```
-  rwx  r-x  r--
│  │││  │││  │││
│  │││  │││  └└└── Others (остальные): r-- (только чтение)
│  │││  └└└─────── Group (группа):     r-x (чтение + вход)
│  └└└──────────── User (владелец):    rwx (чтение + запись + исполнение)
└────────────────── Тип файла: - (файл), d (папка), l (ссылка)
```

### Три базовых права:

| Буква | Значение | Для файла | Для папки |
|-------|----------|-----------|-----------|
| `r` (read) | Чтение | Можно прочитать содержимое | Можно посмотреть список файлов (`ls`) |
| `w` (write) | Запись | Можно изменить/удалить | Можно создавать/удалять файлы внутри |
| `x` (execute) | Исполнение | Можно запустить как программу | Можно **войти** в папку (`cd`) |

> 💡 **Критично для папок:** Если у папки нет `x`, вы не сможете в неё зайти, даже если есть `r`. А если нет `r`, но есть `x` — зайти сможете, но `ls` не сработает (хотя можно обратиться к файлу по имени, если знаете его).

### Числовой формат (для ленивых)

Каждое право — это бит: `r=4`, `w=2`, `x=1`. Складываем:

| Число | Буквы | Значение |
|-------|-------|----------|
| `7` | `rwx` | Всё можно (4+2+1) |
| `6` | `rw-` | Чтение + запись |
| `5` | `r-x` | Чтение + исполнение |
| `4` | `r--` | Только чтение |
| `0` | `---` | Ничего |

Три цифры = `Владелец` `Группа` `Остальные`:

| Число | Расшифровка | Когда использовать |
|-------|-------------|-------------------|
| `755` | `rwxr-xr-x` | Папки и скрипты (владелец пишет, остальные читают) |
| `644` | `rw-r--r--` | Обычные файлы (конфиги, тексты) |
| `700` | `rwx------` | Приватные папки (только владелец) |
| `600` | `rw-------` | Приватные файлы (ключи SSH, `.env`) |

> 🚨 **НИКОГДА не ставьте `777`!** Это значит «любой может делать что угодно». В больнице это нарушение требований безопасности. Если что-то не работает — разберитесь с владельцем и группой, а не открывайте доступ всем.

## 🔧 Часть 5. Изменение прав и владельцев

### 1. `chmod` — изменить права

**Символьный формат** (интуитивный):
```bash
chmod u+x script.sh       # Добавить исполнение для владельца (u=user)
chmod g+w /shared/docs    # Добавить запись для группы (g=group)
chmod o-r secret.txt      # Убрать чтение у остальных (o=others)
chmod a+r public.txt      # Добавить чтение всем (a=all)
```

**Числовой формат** (быстрый):
```bash
chmod 755 /opt/emh/               # Папка: владелец rwx, остальные r-x
chmod 644 /opt/emh/config.yml     # Файл: владелец rw, остальные r
chmod 600 /opt/emh/.env           # Секретный файл: только владелец
chmod -R 755 /opt/emh/scripts/    # Рекурсивно для всей папки
```

### 2. `chown` — изменить владельца и группу

```bash
chown ivanov file.txt              # Сменить владельца на ivanov
chown ivanov:staff file.txt        # Сменить владельца И группу
chown :docker /var/lib/emh/data    # Сменить ТОЛЬКО группу на docker
chown -R www-data:www-data /var/www/emh/  # Рекурсивно для веб-сервера
```

> 💡 **Частая ошибка:** `chown` без `sudo` не сработает, если вы не root. Почти всегда нужно `sudo chown ...`.

### 3. `chgrp` — изменить только группу (редко используется)
```bash
chgrp staff /shared/docs
```
*То же самое, что `chown :staff /shared/docs`, просто другой синтаксис.*

## 🦸 Часть 6. `sudo` и `su`: режим суперпользователя

### `sudo` — выполнить ОДНУ команду от root
```bash
sudo systemctl restart nginx      # Перезапустить nginx
sudo apt update                   # Обновить списки пакетов
sudo nano /etc/nginx/nginx.conf   # Отредактировать системный конфиг
```

*Правила:*
- *`sudo` спрашивает **ваш** пароль, не пароль root.*
- *После первого ввода пароль кэшируется на 15 минут.*
- *Чтобы вы могли использовать `sudo`, ваш пользователь должен быть в группе `sudo` (проверьте: `id`).*

### `su` — переключиться на другого пользователя
```bash
su - postgres         # Переключиться на пользователя postgres (с его окружением)
su - ivanov           # Переключиться на Иванова
exit                  # Вернуться обратно к своему пользователю
```

> ⚠️ **Не сидите под root постоянно!** Работайте под своим пользователем и используйте `sudo` только когда нужно. Случайный `rm -rf` под root может уничтожить систему.

## 🏥 Часть 7. Практические кейсы из больницы

### Кейс 1: «Веб-сервер EMH отдаёт 403 Forbidden»

**Симптом:** Сайт Employee Virtual Portal не открывается, в логах Nginx ошибка `403 Forbidden`.

**Диагностика:**
```bash
# Проверяем, от какого пользователя работает Nginx
ps aux | grep nginx
# Вывод: www-data  1234  ...  nginx: worker process

# Смотрим права на папку с сайтом
ls -la /var/www/emh/
# Вывод: drwxr-x--- 3 root root 4096 Oct 6 09:00 .
#                         ^^^^ ^^^^
#                    Владелец root, группа root!
```

**Проблема:** Nginx работает от `www-data`, а папка принадлежит `root` и группе `root`. У `www-data` нет прав на чтение (`r-x` для группы `root` не помогает, потому что `www-data` не в группе `root`).

**Решение:**
```bash
# Меняем владельца на www-data
sudo chown -R www-data:www-data /var/www/emh/

# Проверяем
ls -la /var/www/emh/
# Вывод: drwxr-x--- 3 www-data www-data 4096 Oct 6 09:00 .
#                         ^^^^^^^^ ^^^^^^^^  ✅
```

### Кейс 2: «Docker-контейнер PostgreSQL не может записать данные»

**Симптом:** Контейнер `emh-postgres-prod` падает с ошибкой `Permission denied` на `/var/lib/postgresql/data`.

**Диагностика:**
```bash
# Смотрим логи контейнера
docker logs emh-postgres-prod
# Вывод: FATAL: data directory "/var/lib/postgresql/data" has wrong ownership
#        HINT: The server must be started by the user that owns the data directory.

# Проверяем права на хосте (папка volume)
ls -la /opt/emh/deploy/data-postgres-prod/
# Вывод: drwxr-xr-x 2 root root 4096 Oct 6 08:00 .
#                         ^^^^ ^^^^
#                    Принадлежит root!
```

**Проблема:** Папка на хосте принадлежит `root`, а PostgreSQL внутри контейнера работает от пользователя `postgres` (обычно `uid=999`).

**Решение:**
```bash
# Узнаём UID пользователя postgres в контейнере
docker exec emh-postgres-prod id postgres
# Вывод: uid=999(postgres) gid=999(postgres) groups=999(postgres)

# Меняем владельца папки на хосте
sudo chown -R 999:999 /opt/emh/deploy/data-postgres-prod/

# Перезапускаем контейнер
docker restart emh-postgres-prod
```

### Кейс 3: «Новый сотрудник, нужно дать доступ к серверу»

**Симптом:** В ИТ-отдел пришёл новый коллега Петров, ему нужен доступ к серверам EMH.

**Решение:**
```bash
# 1. Создаём пользователя с домашней папкой и bash
sudo useradd -m -s /bin/bash petrov

# 2. Задаём временный пароль
sudo passwd petrov
# (Сообщите пароль Петрову лично, попросите сменить при первом входе)

# 3. Добавляем в нужные группы
sudo usermod -aG sudo petrov      # Если нужен sudo (для сисадминов)
sudo usermod -aG docker petrov    # Если нужен доступ к Docker

# 4. Проверяем
id petrov
# Вывод: uid=1002(petrov) gid=1002(petrov) groups=1002(petrov),27(sudo),999(docker) ✅
```

### Кейс 4: «Файл .env не читается сервисом»

**Симптом:** Сервис EMH падает при старте, не может прочитать `.env`.

**Диагностика:**
```bash
ls -la /opt/emh/.env
# Вывод: -rw------- 1 admin admin 512 Oct 6 10:00 .env
#        ^^^^^^^^
#        Только владелец (admin) может читать!
```

**Проблема:** Сервис запускается от другого пользователя (например, через Docker или systemd) и не может прочитать файл.

**Решение:**
```bash
# Вариант А: Дать чтение группе (если сервис в нужной группе)
sudo chmod 640 /opt/emh/.env
sudo chgrp docker /opt/emh/.env

# Вариант Б (для Docker): Docker обычно читает .env от имени того, 
# кто запускает docker compose, так что достаточно:
sudo chmod 644 /opt/emh/.env
# Но помните: .env содержит пароли! 644 — компромисс для удобства.
# В продакшене лучше использовать Docker Secrets или переменные окружения.
```

## 📋 Шпаргалка

| Команда | Что делает | Пример |
|---------|-----------|--------|
| `whoami` | Кто я сейчас | `whoami` → `admin` |
| `id` | Мой UID, GID, группы | `id` → `uid=1000(admin) groups=...` |
| `id user` | Инфо о другом пользователе | `id postgres` |
| `w` | Кто залогинен и что делает | `w` |
| `useradd -m -s /bin/bash name` | Создать пользователя | `sudo useradd -m -s /bin/bash ivanov` |
| `passwd name` | Задать/сменить пароль | `sudo passwd ivanov` |
| `usermod -aG group name` | Добавить в группу | `sudo usermod -aG docker ivanov` |
| `userdel -r name` | Удалить с файлами | `sudo userdel -r ivanov` |
| `chmod 755 file` | Права в числах | `chmod 755 /opt/emh/` |
| `chmod u+x file` | Права символами | `chmod u+x deploy.sh` |
| `chmod -R 644 dir/` | Рекурсивно | `chmod -R 644 /var/www/emh/` |
| `chown user:group file` | Сменить владельца | `sudo chown www-data:www-data /var/www/` |
| `chown -R user dir/` | Рекурсивно | `sudo chown -R 999:999 /data/postgres/` |
| `sudo command` | Выполнить от root | `sudo systemctl restart nginx` |
| `su - user` | Переключиться | `su - postgres` |

### Быстрая диагностика `Permission denied`:
1. `ls -la <файл>` — кто владелец, какие права?
2. `id` — кто я и в каких группах?
3. `ps aux | grep <сервис>` — от какого пользователя работает сервис?
4. Совпадают ли? Если нет → `chown` / `chmod` / `usermod -aG`.
